Personal Music Library Transfer — Privacy Policy

Effective October 24, 2026. Version 2026-10-24.

Operator and purpose

Brian Borg operates Personal Music Library Transfer as a private, local command-line tool for his own music account. It transfers selected playlist references and follows confidently identified artist channels. It is not currently offered to the public. Contact: briborg21@gmail.com.

Information used

The tool reads the owner’s selected iTunes/Apple Music library export, including track titles, artists, albums, ratings, playlist membership and order, and local track identifiers. Through Google authorization, it reads the connected YouTube channel identity, relevant video and channel metadata, playlists and subscriptions. It stores approved recording identifiers, match-review records, transfer progress, verification receipts and API quota estimates locally so interrupted transfers can resume without repeating confirmed changes.

OAuth access and refresh tokens are stored locally to authorize Google API requests. Earlier troubleshooting also retained browser session headers/cookies, network-capture (HAR) files and diagnostic records locally; the official API route does not require these browser credentials, but those older files have not yet been removed. The tool does not request or store the owner’s Google password. It does not copy, download or upload audio files.

Uses and disclosures

Information is used to identify approved matches, create private destination playlists, add approved recordings in source order, follow approved artist channels, verify results and maintain resumable progress. Uncertain or unavailable matches are held for review. The tool sends the identifiers and authorization information required for these operations to Google’s YouTube API Services.

The tool has no advertising, data-sale, public-sharing or model-training feature. Its code does not send library data to a separate migration vendor. Brian uses OpenAI Codex to develop, operate and troubleshoot this tool at his direction. Selected prompts, files and tool outputs may be sent to OpenAI to provide that requested assistance, under the owner’s OpenAI account controls and OpenAI Privacy Policy. The Python client has no integrated AI service, and does not itself send library data to OpenAI. No promise is made here about settings or retention in a separate provider’s account. Google processes data under the Google Privacy Policy. Use of YouTube is subject to the YouTube Terms of Service.

The tool’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Storage and security

Credentials, library exports and migration records are kept in private local files and excluded from the published source repository. Sensitive files use owner-only filesystem permissions. These precautions reduce exposure but are not a guarantee against device compromise. The owner controls access to the computer and any backups.

Retention, revocation and deletion

The owner keeps independent Apple source exports while needed. API-derived data is inventoried separately, including legacy diagnostic files and controlled backups. The owner reviews retained API data and authorization at least weekly, using the local lifecycle tools and documented checklist. The migration checks known local file ages, blocks revoked access and requires weekly authorization validation. File ages do not prove that every record is current; the owner separately reviews the age of the underlying API data. Refresh or delete stored YouTube API metadata within the periods required by the YouTube Developer Policies, no later than 30 calendar days where that rule applies. Delete stored authorized user data as soon as possible and within seven calendar days of a deletion request or authorization revocation where the policies require it. Apply deletion to controlled backups as well. This is an owner-operated process, not a claim of automatic erasure while the computer is offline. The owner must refresh or delete API data before its applicable deadline; authorization checks alone do not refresh stored metadata.

The client provides a local revoke/forget command, which requests token revocation from Google and supports scoped local-data removal. Deletion first offers a preview; no YouTube playlists, subscriptions or saved albums are deleted by local cleanup. The owner can also request local-data deletion by contacting briborg21@gmail.com and revoke the tool’s Google access at Google Account permissions. Revoking access prevents future authorized requests; local copies must also be deleted. Deleting local transfer records does not delete playlists, subscriptions or other data stored by YouTube. Manage those directly in YouTube or another authorized client.

Changes

Update this policy before materially changing the tool’s data collection, use, sharing or audience. The date and version above identify this policy. A new data use requires renewed consent before access.
